### W-T9-02: "Seed from template" overwrites the user's saved writing rules at once, with no confirmation or undo
- **Severity:** 4
- **Where:** CV Studio › "Voice — writing rules" › "Seed from template"
- **Tasks:** T9, T1
- **Capabilities:** UI-cv-voice-seed, R-cv-voice-put, C-voice-dna-md
- **Method:** walkthrough (T9 step 2, Q3)
- **Evidence:** app/ux/evidence/W-T9-02.png
- **Reproduction:**
  1. `node app/ux/sandbox.mjs --state populated --port 4400`, open http://127.0.0.1:4400/#/cv
  2. Scroll to "Voice — writing rules". Note the rules ("# Voice DNA — Alex Rivera (fictional)", "## Never write", "- spearheaded" …).
  3. Click "Seed from template".
  4. Observe: the textarea now holds upstream's template ("# VOICE DNA / Source of truth for my writing voice…"); no dialog, no message. Reload the page: the template is still there — the file was saved, and the user's own rules (including "spearheaded") are gone. Nothing offers to restore them.
- **Notes:** New (not in the heuristics files). Data loss on a one-click secondary button that sits next to the save button, on a page whose task is "don't lose the rules you set up". The button makes sense when `voice-dna.md` does not exist (T1's empty state, whose placeholder recommends it); when the file exists it should confirm, merge, or be hidden. Severity 4: loses user data without warning.

## Verdict

**No — a first-time user is unlikely to complete T9 unaided.** P1 can (they know the voice
file feeds the next PDF). For P2 and P3 the step most likely to stop them is **step 4**:
having saved the rules on CV Studio, they click CV Studio's own "Render this CV" for the
Cobalt Freight CV, see "Finished", and stop — with a re-render that never applied the new
rules (W-T9-06). The out-of-view save message (step 3) is the only hint otherwise. Step 2
carries the worst single risk: "Seed from template" silently overwrites the user's rules on
disk (W-T9-02).
