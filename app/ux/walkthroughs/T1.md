# Cognitive walkthrough — T1: First run from an empty workspace

- **Start state:** `empty` (`node app/ux/sandbox.mjs --state empty --port 4400`)
- **Personas:** P1 (career-ops migrant), P2 (first-timer), P3 (career-changer)
- **Expected path:** `tasks.md` › Expected paths › T1. The path has no completing route: it
  records where the user looks for "give it my CV" and "add a company".
- Walked on 2026-10-04 against a fresh `empty` sandbox (port 4402 during the run; the
  reproductions use 4400).

Summary: 3 steps, 3 with at least one "no". 4 findings (W-T1-01 … W-T1-04).

---

## Step 1 — From the first screen (Pipeline), give the app the CV

What is on screen: the add-job box ("Paste a job posting URL…", "Evaluate now" and "Add to
inbox" both disabled), the grey line "No cv.md in the data directory yet", a collapsed
"1 data issue found" (expanding it reads "`tracker-missing`: No applications tracker yet —
run an evaluation to create one."), and "No applications match these filters."

| Q | Answer | Reason |
|---|---|---|
| Q1 | **Yes** (all) | The goal says the app needs the CV, and the screen confirms it ("No cv.md…"). |
| Q2 | **No** (all) | There is no control that accepts a CV: no upload, no paste box, no link from the "No cv.md" line. The only text field is for a job URL. |
| Q3 | **No** (P2, P3) / Yes-ish (P1) | P1 reads "cv.md in the data directory" as "write the file by hand", which they know how to do but did not come here for. P2 and P3 do not know what "cv.md" or "the data directory" are; "run an evaluation to create one" points them at a button that is disabled for lack of the CV. |
| Q4 | n/a | No action is possible. |

### W-T1-01: The first screen names the missing CV but offers no way to provide it
- **Severity:** 4
- **Where:** Pipeline › add-job box › "No cv.md in the data directory yet"; "1 data issue found"
- **Tasks:** T1
- **Capabilities:** UI-pipeline-evaluate-now, R-agent-status, C-cv-md
- **Method:** walkthrough (T1 step 1, Q2/Q3)
- **Evidence:** app/ux/evidence/W-T1-01.png
- **Reproduction:**
  1. `node app/ux/sandbox.mjs --state empty --port 4400`, open http://127.0.0.1:4400/
  2. Expand "1 data issue found" and "What happens when I click Evaluate now?".
  3. Observe: "No cv.md in the data directory yet" is plain text; nothing on the page accepts a CV. The data issue says to "run an evaluation", which the missing CV blocks.
- **Notes:** Same problem as H-empty-state-01 and H-empty-state-02. P2's card: "being asked to edit files by hand" is a give-up condition — and this is the very first screen.

## Step 2 — Look for the CV in "CV Studio"

What is on screen: "CV" select with a single option, "Sample CV (fictional)" — "A fictional
CV, for trying themes before you have generated one." — the Look tokens, Themes, a preview
of the sample CV, and further down "Voice — writing rules" with a large empty textarea
("No voice-dna.md yet. Seed it from upstream's template, or write your own rules.") and a
primary "Save voice rules" button.

| Q | Answer | Reason |
|---|---|---|
| Q1 | **Yes** (all) | After step 1 fails, "CV Studio" is the obvious next stop for every persona. |
| Q2 | **Yes** | "CV Studio" is in the top nav. |
| Q3 | **No** (all) | The "CV" select offers only the fictional sample; nothing says how to put your own CV here. Worse, the page's one big editable area is the Voice textarea, whose placeholder ("…write your own rules") and primary "Save voice rules" button invite a paste. |
| Q4 | **No** (P2, P3) | Pasting the CV into that textarea and clicking "Save voice rules" succeeds without a visible message: the status beside the button changes to the file path `…\voice-dna.md` (any save message is at the top of the page, out of view). The CV has become the writing-rules file; `cv.md` still does not exist, and Pipeline still says "No cv.md…". Nothing tells the user they used the wrong box. |

### W-T1-02: CV Studio's "CV" select offers only a fictional sample, with no way to add your own
- **Severity:** 3
- **Where:** CV Studio › "CV" select ("Sample CV (fictional)")
- **Tasks:** T1
- **Capabilities:** UI-cv-document, C-cv-md
- **Method:** walkthrough (T1 step 2, Q3)
- **Evidence:** app/ux/evidence/W-T1-02.png
- **Reproduction:**
  1. `node app/ux/sandbox.mjs --state empty --port 4400`, open http://127.0.0.1:4400/
  2. Click "CV Studio".
  3. Observe: "CV" lists only "Sample CV (fictional)"; the hint says it is "for trying themes before you have generated one". No upload, paste or "use my CV" control.
- **Notes:** Same problem as H-empty-state-06. The page named after the CV is where every persona looks; the hint even implies CVs are "generated", leaving P2 unsure where their own one goes.

### W-T1-03: The Voice textarea is the only big text box, accepts a pasted CV and saves it as writing rules without warning
- **Severity:** 3
- **Where:** CV Studio › "Voice — writing rules" › textarea and "Save voice rules"
- **Tasks:** T1, T9
- **Capabilities:** UI-cv-voice-text, UI-cv-voice-save, C-voice-dna-md
- **Method:** walkthrough (T1 step 2, Q3/Q4)
- **Evidence:** app/ux/evidence/W-T1-03.png
- **Reproduction:**
  1. `node app/ux/sandbox.mjs --state empty --port 4400`, open http://127.0.0.1:4400/#/cv
  2. Scroll to "Voice — writing rules". Paste the T1 CV text into the empty textarea.
  3. Click "Save voice rules".
  4. Observe: the status beside the buttons changes from "voice-dna.md does not exist yet" to the bare path `C:\…\voice-dna.md`. Nothing near the button says what was saved or that this is not the CV (the page's save message, "voice-dna.md saved. It applies to the next cover letter or PDF.", is printed at the top of CV Studio, out of view — see W-T9-03). Return to Pipeline: "No cv.md in the data directory yet" is unchanged.
- **Notes:** New (no H- equivalent). A first-timer looking for "where do I paste my CV" finds exactly one large textarea on the CV page and a primary button under it. The save turns their CV into the rules file every future PDF and letter session reads, and the feedback (a file path) neither confirms the intent nor flags the mismatch. P2 concludes "it saved my CV" and moves on; the failure only surfaces later.

## Step 3 — "Sources" → add Kestrel Media

What is on screen: a collapsed "1 issue(s) in portals.yml" (expands to "`portals-missing`: No
portals.yml yet — add a company to create one."), "Scan now" (enabled), "0 URL(s) waiting
to be evaluated", "Tracked companies (0)" with "Add" (disabled) and "Nothing here yet.",
"Job boards (0)" with "Add" (disabled). "How sources work" explains providers and the
"Last seen" column, not how to start.

| Q | Answer | Reason |
|---|---|---|
| Q1 | **Yes** (all) | The goal names the company and careers URL. |
| Q2 | **Yes** (P1) / **Partly** (P2, P3) | P1 maps "Sources" to `portals.yml`. P2 and P3 have to guess that "companies to keep an eye on" lives under "Sources"; "Tracked companies" confirms it once they are there. |
| Q3 | **No** (P2, P3) | Two "Add" buttons, under "Tracked companies" and "Job boards"; a careers URL on Greenhouse could belong to either, and nothing says which. Moot here because… |
| Q4 | **No** (all) | …both "Add" buttons are disabled, with no tooltip or reason, while the issue text tells the user to "add a company to create one". The step cannot be taken. |

### W-T1-04: Both "Add" buttons on Sources are disabled with no reason, while the issue says "add a company"
- **Severity:** 4
- **Where:** Sources › "Tracked companies (0)" › "Add"; "Job boards (0)" › "Add"; "1 issue(s) in portals.yml"
- **Tasks:** T1
- **Capabilities:** UI-sources-add-company, R-portals-create, C-portals-yml
- **Method:** walkthrough (T1 step 3, Q4)
- **Evidence:** app/ux/evidence/W-T1-04.png
- **Reproduction:**
  1. `node app/ux/sandbox.mjs --state empty --port 4400`, open http://127.0.0.1:4400/
  2. Click "Sources". Expand "1 issue(s) in portals.yml". Hover either "Add".
  3. Observe: the issue reads "No portals.yml yet — add a company to create one."; both "Add" buttons are greyed out, with no tooltip; "How sources work" says nothing about getting started.
- **Notes:** Same problem as H-empty-state-03. This is where every persona stops: even P1, who would edit `portals.yml` by hand, has been told by the page that adding here creates it.

---

## Verdict

**A first-time user cannot complete T1 unaided** — no persona can; there is no route
through the UI for either criterion. The step most likely to stop them is **step 1**: the
very first screen says the CV is missing and offers nothing to do about it. P2 and P3 then
try CV Studio, where the realistic outcome is worse than stopping — pasting the CV into the
Voice box and believing it worked (W-T1-03). Sources (step 3) is a hard stop for everyone.
